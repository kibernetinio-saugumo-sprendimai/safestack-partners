# Contributing to SafeStack partners

Thank you for improving this catalogue. Contributions should make an external resource easier to understand, safer to use and easier to verify.

## Before opening a pull request

1. Check for an existing issue or entry before proposing a duplicate.
2. Prefer the resource's official URL and primary documentation.
3. Confirm that the resource is relevant to security learning, defense, verification or open-source work.
4. Do not include credentials, private keys, personal data or confidential incident details.
5. Mark unverified or third-party resources clearly; a listing is not a partnership endorsement.

## Pull requests

- Explain the change and why it improves the catalogue.
- Keep descriptions factual, concise and maintainable.
- Use the pull request checklist and link related issues where applicable.
- Check Markdown, YAML and SVG syntax locally before submitting.
- Keep security-sensitive changes small so they can be independently reviewed.

Maintainers may request a source link, a scope clarification or a safer wording before merging.
